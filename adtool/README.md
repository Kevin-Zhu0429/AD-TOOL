# CYES 广告工作台

公司内网工具:自动广告 / 手动广告批量开发 + 分站点否定词库。

## 目录

    adtool/
      server/    后端 Node + Express + SQLite
      web/       前端 React + Vite

## 首次安装

    cd server
    npm install
    copy .env.example .env      # 然后改掉里面的 SESSION_SECRET
    node src/seed.js kevin 凯文 你的密码

    cd ../web
    npm install

## 开发模式(两个终端)

    cd server && node src/index.js      # 后端 8080
    cd web    && npm run dev            # 前端 5173,发这个的 Network 地址给同事

## 正式模式(一个进程,推荐给同事用)

    cd web && npm run build
    cd ../server && node src/index.js   # 只开 8080,前端由它一起托管

## 两种开广告的页面

| 页面 | 投放类型 | 填什么 | 出的表 |
|---|---|---|---|
| 自动广告 | 自动 | SKU + 溢价组合 + 命名规则,出价按 CPC 基数自动折算 | 一个任务几十条活动 |
| 手动广告 | 手动 | SKU + 自己粘贴的关键词或 ASIN,出价自己填 | 一个任务一条活动 |

手动广告页从桌面版「AMAZON 广告批量生成器」搬过来,校验和自检口径跟桌面版一致:

* **关键词投放** —— 精准 / 词组 / 广泛三种匹配各一个粘贴框,各自给出价(留空就用广告组默认竞价)。
  写进表里时精准自动加 `[词]`、词组自动加 `"词"`、广泛不加;粘进来时自带的引号或方括号先去掉再统一加。
* **商品投放** —— ASIN 精准 / ASIN 扩展 / 品类三种。填纯 ASIN 即可,自动写成 `asin="B0…"`;
  品类填纯数字 ID。同一条活动里同一个表达式只能出现一次。
* 一个广告组要么打关键词、要么打商品定向,亚马逊不允许混投,所以两种方式二选一。
  勾上「每种类型单独一个广告组」会按类型拆成多个广告组(组名加类型后缀),SKU 和否定词每个组都写一遍。
* 关键词和 ASIN **一律自己粘贴**,这一页不接任何关键词库 / 产品库 / 打印机型号库。
* 否定词照旧联动本站词库:A–E 五类照常勾选,系列广告的 D 类联动否定也一样能用。
  词库里设成活动级的否定只写一次,组级的每个广告组各写一遍。

亚马逊的限制页面会当场提示:关键词加匹配符后不超过 80 字符、超过 10 个单词会提醒、
出价不低于 0.02、每日预算低于 1.00 会提醒、活动名不超过 128 字符、开始日期必须是 8 位有效日期、
投放的 ASIN 不能同时又在否定 ASIN 里。有硬错误时「生成总表并下载」是灰的;
真生成前还会照桌面版那套逐行自检一遍,不通过就不出文件。

## 五类否定词库

| 类 | 名称 | 存法 | 谁维护 | 节奏 | 字段 |
|---|---|---|---|---|---|
| A | 无名词 | 每个站点一份 | 运营 / 国家管理员 | 零星补充 | 否定词 |
| B | 非售品牌 | 欧洲 / 美洲各一份 | 商品部 | 低频 | 品牌 |
| C | 非售流量干扰墨盒 | 欧洲 / 美洲各一份 | 商品部 | 月度 | 墨盒型号、打印机型号、竞品ASIN |
| D | 在售墨盒型号和相关打印机 | 欧洲 / 美洲 / 澳洲各一份 | 商品部 | 月度 | 墨盒原装品牌、墨盒型号、打印机系列、打印机型号 |
| E | 原装竞品 ASIN | 每个站点一份 | 商品部 | 待定 | ASIN、品牌、对应墨盒型号 |

区域库只存一份:**欧洲传德国、美洲传美国**,同区其他站点自动跟着变,不用一个站一个站传。
澳洲目前只有 D 类。E 类数据格式还没定,先按 ASIN + 品牌 + 对应墨盒型号存着,默认不往广告里带。

导入导出都在词库页:导入认表头(「欧洲墨盒型号」这种前缀也认),认不出就按列序读;
「整表替换」是先清空这一类再写,月度整表更新用。批量添加框里从 Excel 直接粘贴即可,
多列词库列之间是 Tab —— D 类的墨盒型号本身写成「575, 576」,所以逗号不当分隔符。

## D 类怎么联动否定

自动广告页和手动广告页,每个任务都先选是**混合广告**还是**系列广告**:

* 混合广告 —— D 类不参与,只带 A/B/C(和勾了的 E)。
* 系列广告 —— 选中要投的墨盒型号(比如 301),D 类会反推出该否掉的东西:
  * 其余墨盒型号全否;「575, 576」这种一起卖的,选中一个,同组的另一个也留着;
  * 其余打印机型号全否;同一个数字在别的系列里也出现过时(比如两个系列都有 2540),
    自动写成「DeskJet 2540」这种带系列名的形式,不会误伤在投的机型;
  * 正在投的那个系列的打印机,一个都不会被否掉。

欧洲 D 类有一千多行,墨盒 + 打印机一起否会超过亚马逊每条活动 1000 个否定词的上限,
所以「联动否定」可以切成只否墨盒型号或只否打印机型号,超限时页面会提示。

D 类同时也是打印机型号库:运营在词库页可以按品牌、打印机系列筛选和搜索。

## 角色

| 角色 | 自动广告 | 手动广告 | A 类无名词 | B/C/D/E | 账号管理 |
|---|---|---|---|---|---|
| owner    | 全部站点     | 有             | 全部站点可编辑     | 可编辑 | 有 |
| admin    | 分配到的站点 | 超管开了才有   | 分配到的站点可编辑 | 只读   | 无 |
| operator | 分配到的站点 | 超管开了才有   | 分配到的站点可编辑 | 只读   | 无 |

admin 和 operator 现在权限完全一样,只是名称上区分职级。
在「账号管理」里给账号勾上**商品部维护权**,他就能改所有区域的 B/C/D/E,并且看得到全部站点;
纯商品部的账号可以不挂站点。词库的「开广告时怎么用」那几个开关归站点负责人管,商品部不碰。

**手动广告使用权**同样在「账号管理」里逐个勾。这一页还在试用期,新老账号默认都没有 ——
没勾的人导航栏和首页都看不到「手动广告」,只有自动广告;超级管理员天然有。

一个账号可以同时负责多个站点,在「账号管理」里勾选,登录后从右上角切换。
改了谁的站点/角色/状态/手动广告权限,对方下一个请求就生效,刷新一下页面就看得到,不用重新登录。

## 备份

数据全在 server/data/ 目录。每天拷一份 adtool.db 到 Z 盘即可。
注意:数据库文件本身不能放在 Z 盘(SMB 文件锁不可靠,会损坏)。
