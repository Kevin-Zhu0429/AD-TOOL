# CYES 广告工作台

公司内网工具:自动广告 / 手动广告批量开发 + 广告优化工作台 + 分站点否定词库 +
各账号自己的 SKU 库 + 分市场产品库与竞品竞争力分析。

## 目录

    adtool/
      server/    后端 Node + Express + SQLite
      web/       前端 React + Vite

## 首次安装

    cd server
    npm install
    copy .env.example .env      # 然后改掉里面的 SESSION_SECRET
    node src/seed.js kevin 凯文 你的密码

    cd ../web
    npm install

## 开发模式(两个终端)

    cd server && node src/index.js      # 后端 8080
    cd web    && npm run dev            # 前端 5173,发这个的 Network 地址给同事

## 正式模式(一个进程,推荐给同事用)

    cd web && npm run build
    cd ../server && node src/index.js   # 只开 8080,前端由它一起托管

## 两种开广告的页面

| 页面 | 投放类型 | 填什么 | 出的表 |
|---|---|---|---|
| 自动广告 | 自动 | SKU + 溢价组合(不填也能开,就是不加溢价) + 命名规则,出价按 CPC 基数自动折算 | 一个任务几十条活动 |
| 手动广告 | 手动 | SKU + 自己粘贴的关键词或 ASIN,出价自己填、或者按目标 CPC 反推 | 一个任务一条活动 |

**填的东西不会丢**:两个页面的任务都会自动存在本机浏览器里(按页面 + 站点各存一份,
只存本地、不上传服务器)。切到别的页面再回来、手滑刷新、关了标签页第二天再开都还在,
生成完继续改也一样。不想要了点操作条上的**清空重来**,连草稿一起删掉。

手动广告页从桌面版「AMAZON 广告批量生成器」搬过来,校验和自检口径跟桌面版一致:

* **关键词投放** —— 精准 / 词组 / 广泛三种匹配各一个粘贴框,各自给出价(留空就用广告组默认竞价)。
  写进表里时精准自动加 `[词]`、词组自动加 `"词"`、广泛不加;粘进来时自带的引号或方括号先去掉再统一加。
* **商品投放** —— ASIN 精准 / ASIN 扩展 / 品类三种。填纯 ASIN 即可,自动写成 `asin="B0…"`;
  品类填纯数字 ID。同一条活动里同一个表达式只能出现一次。
* 一个广告组要么打关键词、要么打商品定向,亚马逊不允许混投,所以两种方式二选一。
  勾上「每种类型单独一个广告组」会按类型拆成多个广告组(组名加类型后缀),SKU 和否定词每个组都写一遍。
* **出价**两种填法,在「出价怎么定」那里切:
  * *直接填出价* —— 出价就是写进表里的数,下面的「最终 CPC」表会算出各广告位实际会被扣到多少钱。
  * *按目标 CPC 反推* —— 填想要的落地 CPC,按 `出价 = 目标CPC ÷ ((1+溢价) × 广告位系数)` 折算,
    口径和自动广告页完全一致:按最贵的那个广告位算,保证任何位置的落地 CPC 都不超过目标;
    溢价填 0 的广告位不打系数;只有「提高和降低」才用系数(仅降低 / 固定竞价一律 ×1)。
    这时候每种匹配 / 定向类型的出价框填的也是**目标 CPC**,留空就用上面那个,
    框下面直接写着折算成多少出价。折算完低于 0.02 会当场拦下来。
* **投放**的关键词和 ASIN 一律自己粘贴,不接任何关键词库 / 产品库 / 打印机型号库;
  只有「投放 SKU」可以从自己的 SKU 库挑(见下一节)。
* 否定词照旧联动本站词库:A–E 五类照常勾选,系列广告的 D 类联动否定也一样能用。
  词库里设成活动级的否定只写一次,组级的每个广告组各写一遍。
  想单独否几个机型,「本任务额外否定」里可以从 D 类打印机库挑(见「从打印机库挑否定词」)。

亚马逊的限制页面会当场提示:关键词加匹配符后不超过 80 字符、超过 10 个单词会提醒、
出价不低于 0.02、每日预算低于 1.00 会提醒、活动名不超过 128 字符、开始日期必须是 8 位有效日期、
投放的 ASIN 不能同时又在否定 ASIN 里。有硬错误时「生成总表并下载」是灰的;
真生成前还会照桌面版那套逐行自检一遍,不通过就不出文件。

## SKU 库

**每个账号一份自己的**,别人看不到,大家只传自己负责的品牌。模板七列:

    国家 | 品牌 | 型号 | 套组 | SKU | 在库库存 | 在途库存

* 国家填站点码(ES / DE / US…),写「西班牙」这种中文名也认;SKU 必填,其余选填。
* 导入方式:下载模板填好导 Excel,或者直接从 Excel 复制粘贴(列之间是 Tab,也认 `~` 和 `|`)。
  SKU 和型号本身带 `-`,所以不拿它当分隔符。
* 同一个国家里同一个 SKU 再传一次是**更新库存**,不会变成两条。
  勾「整表替换」只清掉这批数据里出现过的那几个国家,传 ES 的表不会动 DE。
* 开广告时(自动、手动都一样)在「投放 SKU」那里点**从 SKU 库选**:
  按当前站点筛出来,输型号搜(输 301 会把 301XL 一起查出来,PG-545 输 545 也能查到),
  勾好之后追加填入或覆盖填入。库存会显示在后面,在库和在途都是 0 的标成「缺货」。
* 超级管理员多一个「全部账号(只读)」页签,能看到谁传了什么,但只能改自己的行。

### 船长 BI 库存同步

服务器配置 `CAPTAIN_CLIENT_ID` 和 `CAPTAIN_CLIENT_SECRET` 后，超级管理员在
「账号管理 → 船长库存」读取店铺，并按“网站账号 + 品牌 + 国家”保存绑定。各账号可在自己的
SKU 库点击「同步船长库存」，超级管理员也可统一同步全部已启用绑定。

库存来源为 `/v1/open_fba/inventory_list`：可售数量写入在库库存，已发货、接收中、处理中三项
相加写入在途库存。同步只更新已存在且账号、品牌、SKU 匹配的行，不自动新建 SKU，也不覆盖型号、
套组等人工资料；没有匹配的船长 SKU 会计入结果提示。

欧洲区（ES / DE / FR / IT / UK）按同一账号、同一品牌和 SKU 汇总所有已绑定欧洲店铺，合计值
写入该品牌每个欧洲国家的同名 SKU 行。US / CA / AU 仍按绑定国家分别更新。首次同步按
`CAPTAIN_INITIAL_LOOKBACK_DAYS` 分成不超过 31 天的时间窗回查，后续增量同步保留 5 分钟重叠；
每家店的最后库存快照存入 SQLite，避免某个 SKU 本轮未变化时被少算。

## 广告组合库

每个账号、每个站点分别保存自己的广告组合库，使用两列格式：

    广告组合编号 | 广告组合名称

可以导入 Excel / CSV，也可以直接从 Excel 复制两列粘贴。相同广告组合编号再次导入会更新名称；整表替换只影响当前账号、当前站点。

自动广告和手动广告会按“投放 SKU → 当前账号 SKU 库型号 → 广告组合名称”自动填写广告组合编号。例如 SKU 型号 `540` 或 `540XL` 会匹配名称中的 `540 Series`。同一任务的 SKU 出现两个或更多系列时匹配名称含“混投”的组合。SKU 未入库、未填写型号、没有对应 Series / 混投组合，或同一分类有多个候选时，页面显示具体提示且不猜测；仍可从下拉框手动选择库内组合，或手填其他编号。

## ABA 报告

首页或顶部导航进入 **ABA 报告 → 品牌视图**，选择原始品牌搜索查询绩效 CSV 周报，核对品牌、周数、日期和行数后点 **上传并保存**。支持一次上传多周，当前站点必须与文件一致。ASIN 视图支持原始 CSV 和合并 XLSX，详见下文。

每个登录账号仅能访问自己的报告，包括超级管理员。数据持久写入现有 `DATA_DIR/adtool.db`，随服务器数据库备份与迁移；无需额外存储服务。服务器启动自动创建新表。相同账号、站点、品牌、同一周再传会更新该周，其他周保留，相同文件不重复累计。

选择一周或多周，输入 `305` 可显示所有包含 `305` 的搜索词，也会通过区域 D 库和跑偏词同一套解释器显示对应机型词。可关闭机型关联；候选机型与墨盒在明细中标明。没有 D 库时仅做原词包含匹配。

明细与 ASIN 视图使用相同结构：机型识别、搜索查询、市场 IMP、市场点击 TT、市场购买 TT、市场 CVR、品牌 IMP、品牌点击、品牌购买、品牌 CVR、品牌占有率。搜索词下方保留日期与报告周数，点击可排序列先降序、再次升序。多周默认合并相同搜索查询，数量相加后重算比例；可取消合并逐周对照。市场和品牌 CVR 分别按各自购买 ÷ 点击，品牌占有率按品牌购买 ÷ 市场购买，零分母显示「—」。

升级前已保存的品牌报告缺少品牌曝光、点击和购买字段，页面提示重新上传原报告；重传补齐该周，不重复累计。缺失值显示「—」，不会当成零或计算出虚假的比例。

搜索 `305` 后，词类型可选 **仅机型词** 或 **仅墨盒词（不含机型）**。这两种模式按 D 库核对墨盒归属，不会只因 `3050`、`TS305` 包含 `305` 就纳入 305 系列。含机型的混合搜索词不进入仅墨盒词。

显示方式选 **机型分类汇总**，按机型查看搜索词数量以及同口径的市场、品牌指标，展开分类后查看其中的搜索词（独立分页）。HP 的 `2820`、`2820e`、`2820.e` 合并到相同机型；多个候选或多个机型单列，不重复分配数据。汇总覆盖全部所选周和筛选结果，不局限于当前页。没有机型的词在全部搜索词模式下进入“未归类机型词”。

明细默认每页 100 条，可选 25 / 50 / 100 / 200 / 500 条；表格增高并提供“专注明细”模式，暂时收起上传、报告周和趋势区域，保留搜索与筛选。趋势图和总数始终按过滤后的原始周记录计算，仅统计报告收录词。

开发验证：`cd web` 后运行 `npm test`、`npm run lint`、`npm run build`；后端运行 `node --test tests/aba.test.js`。浏览器测试见 `web/tests/aba.browser.mjs`。Docker 构建同时复制 `shared/`，升级时需重建前端并重启服务端。

## 产品情报导入

产品表支持两种导入方式:

* **全市场月度表**:优先读取名称包含「干净的数据源」的工作表,按 A 列「国家」自动拆到
  ES / DE / FR / IT / UK / US / CA / AU 各自的产品库。在哪个站点页面上传都一样;
  写入前会一次性校验文件中的全部国家和账号权限,有问题整批不导入。
* **旧版单站点表**:没有国家列时继续导入当前站点,兼容原来的卖家精灵产品表。

全市场表直接读取墨盒系列、颜色套组、品牌和价格字段;当前月度模板对应
C 列「墨盒系列」、D 列「颜色套组」、G 列「品牌」、N 列「ASIN」、P 列「价格($)」。
同一国家相同 ASIN 再次上传会更新原记录,不会跨国家串数据;文件里没有出现的国家不会被清空或修改。
手工改过的品牌和颜色套组仍优先保留,其余字段随月度表更新。

## 广告优化工作台(试用中)

从「批量表工作台 V7」搬进来的那一套,现在是站内的一页。整份批量表**只在本机浏览器里解析,不上传服务器**。

用法:后台 广告 → 批量操作 → 下载广告活动(日期范围就是这一期的周期,建议连搜索词报告一起勾),
把 xlsx 拖进来或点「载入本期批量表」。左边按活动列表筛(危险 / 关注 / 有花费 / 零曝光 / 已暂停 / 已改动),
右边逐条看广告位、SKU、投放、否定、搜索词,竞价 / 预算 / 溢价 / 状态直接在表里改,
搜索词一点就进变更清单。「数据分析」视图有 SKU 矩阵、搜索词分析、投放矩阵、广告位汇总、组合汇总五个面板。
改完点「导出批量表」,只出改动行,回后台走「上传批量文件」。改到一半可以「保存进度」存成 json,下次配同一份表载回来。

超大批量表会自动改用逐行读取，页面显示解析阶段、进度和已读取行数，可随时取消。文件仍只在本机浏览器处理；大文件为避免再次生成数百 MB 的完整工作表，固定只导出改动行。

### 按时间段看数据

批量表本身不带日期,一份表就是你下载它时选的那个日期范围 —— 所以这里按「周期」来管:

* 第一份载入的是**基准表**,结构和导出都以它为准;再用「＋ 载入其他周期」把别的周期加进来,
  后加的只留各层指标和搜索词(对不上基准表的活动会被忽略,加之前会告诉你对上了多少条)。
* 周期从文件名里猜(`...2025-07-14_2025-07-20.xlsx`、`7.14-7.20` 都认),猜不到就在弹窗里自己填,
  之后点周期标签上的「改」也能改。
* 时间段选好起止日期(或者用「近 7 / 14 / 30 天」,以最新一期的结束日为准),
  沾边的周期都会计入,全店 KPI、活动列表、SKU 矩阵、搜索词全部按这几期重算。
  只有部分落在时间段里的那几期会标成虚线,并在右边写明是整期算进来的 —— 批量表拆不到天。
  某一期不想要,点它的标签就能排除;手动点过的以手动为准。
* 从后台「报告 → 搜索词」按**每日**下载的报告带日期列,这种数据能精确到天:
  载入时选它算哪一期,之后时间段筛选会按天切。

改动清单和导出始终只认基准表那一份,和选了哪几期无关。

## 五类否定词库

| 类 | 名称 | 存法 | 谁维护 | 节奏 | 字段 |
|---|---|---|---|---|---|
| A | 无名词 | 每个站点一份 | 运营 / 国家管理员 | 零星补充 | 否定词 |
| B | 非售品牌 | 欧洲 / 美洲各一份 | 商品部 | 低频 | 品牌 |
| C | 非售流量干扰墨盒 | 欧洲 / 美洲各一份 | 商品部 | 月度 | 墨盒型号、打印机型号、竞品ASIN |
| D | 在售墨盒型号和相关打印机 | 欧洲 / 美洲 / 澳洲各一份 | 商品部 | 月度 | 墨盒原装品牌、墨盒型号、打印机系列、打印机型号 |
| E | 原装竞品 ASIN | 每个站点一份 | 商品部 | 待定 | ASIN、品牌、对应墨盒型号 |

区域库只存一份:**欧洲传德国、美洲传美国**,同区其他站点自动跟着变,不用一个站一个站传。
澳洲目前只有 D 类。E 类数据格式还没定,先按 ASIN + 品牌 + 对应墨盒型号存着,默认不往广告里带。

导入导出都在词库页:导入认表头(「欧洲墨盒型号」这种前缀也认),认不出就按列序读;
「整表替换」是先清空这一类再写,月度整表更新用。批量添加框里从 Excel 直接粘贴即可,
多列词库列之间是 Tab —— D 类的墨盒型号本身写成「575, 576」,所以逗号不当分隔符。

## D 类怎么联动否定

自动广告页和手动广告页,每个任务都先选是**混合广告**还是**系列广告**:

* 混合广告 —— D 类不参与,只带 A/B/C(和勾了的 E)。
* 系列广告 —— 选中要投的墨盒型号(比如 301),D 类会反推出该否掉的东西:
  * 其余墨盒型号全否;「575, 576」这种一起卖的,选中一个,同组的另一个也留着;
  * 其余打印机型号全否;同一个数字在别的系列里也出现过时(比如两个系列都有 2540),
    自动写成「DeskJet 2540」这种带系列名的形式,不会误伤在投的机型;
  * 正在投的那个系列的打印机,一个都不会被否掉。

选投放型号的搜索框同样认逗号分开的多个型号(`305, 304`),筛出来之后可以「全选搜到的」一次勾上。

欧洲 D 类有一千多行,墨盒 + 打印机一起否会超过亚马逊每条活动 1000 个否定词的上限,
所以「联动否定」可以切成只否墨盒型号或只否打印机型号,超限时页面会提示。

D 类同时也是打印机型号库:运营在词库页可以按品牌、打印机系列筛选和搜索。

## 后台否定助手(D 类当型号库单独用)

不走批量表、直接在亚马逊后台手动开广告 / 手动否定的时候也能用这个库:
词库页切到 **D 类**,右上角点**后台否定助手**。

* 搜之前先选**搜哪一列**:**墨盒型号**(默认)、**打印机机型**、**全部**。
  305 这种数字在别的系列里可能是机型号(墨盒 302、机型 3050),不分开搜就会一起出来 ——
  只想要 305 墨盒的行就用默认的墨盒型号那一列;想按机型找就切到打印机机型,
  系列名和机型号都能搜(`DeskJet`、`2540` 都行)。
* 搜索框一次搜多个型号:`305, 304, 3720` —— **逗号 / 顿号 / 分号 / 换行分开的是「或」**,
  空格分开的是「并且」(`hp deskjet`,「全部」那一列下才有意义),从 Excel 整列复制粘进来也认。
  哪个词没搜到会单独标出来,并写明是在哪一列没搜到。
* 搜完默认把搜到的行全勾上,可以再手动加减;什么都没搜时一个都不勾,免得手一抖复制走一千多个词。
* 两种出词方式:
  * **否定勾中的** —— 勾谁否谁,选要打印机型号、墨盒型号还是两个都要。
  * **只投这些型号,否掉其余** —— 按勾中的墨盒型号整库反推,和系列广告的联动否定同一套算法,
    所以后台手动开的系列广告和工具生成的口径一致;也能切成只否墨盒或只否打印机。
* 出词框可以选每行一个 / 逗号分隔 / 空格分隔,点**复制全部**,直接粘进后台的否定词框。
* 打印机数字在别的系列里也出现过时,给的是带系列名的写法(例 `DeskJet 2540`),不会误伤在投的机型。

开广告页的「从打印机库选」也加了**复制**按钮:挑好的词既可以写进本任务,也可以直接复制去后台。

## 从打印机库挑否定词

联动否定是整库反推,想单独否掉某几个机型不用自己去词库页抄 —— 自动广告页和手动广告页的
「本任务额外否定」里点**从打印机库选**,直接在 D 类库里搜:

* 搜框里输墨盒型号或打印机机型,**逗号分开一次搜多个型号**(`305, 304`),空格分开的要都命中(`hp deskjet`);
  输 301 会把 301XL 一起查出来,输 301XL 也能查到 301,PG-545 输 545 也能查到。
  再配上品牌、打印机系列两个下拉筛。
* 「加哪一列」决定写进去的是**打印机型号**(默认)、**墨盒型号**,还是两个都要。
* 打印机数字在别的系列里也出现过时(比如两个系列都有 2540),列表里会显示成
  `2540 → OfficeJet 2540`,写进否定词的是带系列名的那个,口径和联动否定一致,不会误伤在投的机型。
* 「加到」选写进哪个框:活动级 / 广告组级 × 否定词组 / 否定精准,默认活动级否定词组。
* 系列广告已经选中要投的墨盒型号时,对应的行会标上**在投**并且默认不勾,勾了会提示一句。
* 筛出来不超过 200 行时默认全勾;列表一次最多显示 400 行,再多就搜细一点。
  写进去的词会和框里已有的按大小写不敏感去重,加完告诉你实际加了几个。

## 角色

| 角色 | 自动广告 | 手动广告 | 广告优化 | 产品情报 | SKU 库 | A 类无名词 | B/C/D/E | 账号管理 |
|---|---|---|---|---|---|---|---|---|
| owner    | 全部站点     | 有           | 有           | 有           | 自己的 + 可看全部 | 全部站点可编辑     | 可编辑 | 有 |
| admin    | 分配到的站点 | 超管开了才有 | 超管开了才有 | 超管开了才有 | 自己的            | 分配到的站点可编辑 | 只读   | 无 |
| operator | 分配到的站点 | 超管开了才有 | 超管开了才有 | 超管开了才有 | 自己的            | 分配到的站点可编辑 | 只读   | 无 |

admin 和 operator 现在权限完全一样,只是名称上区分职级。
在「账号管理」里给账号勾上**商品部维护权**,他就能改所有区域的 B/C/D/E,并且看得到全部站点;
纯商品部的账号可以不挂站点。词库的「开广告时怎么用」那几个开关归站点负责人管,商品部不碰。

**手动广告使用权**、**广告优化使用权**和**产品库与竞品分析使用权**都在「账号管理」里逐个勾。
新老账号默认都没有 —— 没勾的人导航栏、首页和对应更新日志都看不到;超级管理员天然有。

一个账号可以同时负责多个站点,在「账号管理」里勾选,登录后从右上角切换。
改了谁的站点/角色/状态/试用功能权限,对方下一个请求就生效,刷新一下页面就看得到,不用重新登录。

## 更新日志和版本号

首页最下面有一块**更新日志**,右下角常驻当前**版本号**(广告优化那一页底部有它自己的操作条,
那里不显示)。发新版之后同事一登录就会自动弹一次更新日志,关掉就记成看过,不再自动弹,
直到下一次发新版;想再看点右下角的版本号或首页的「查看全部」。

看到哪一版记在**账号**上(users.seen_version),不是浏览器里 —— 换台电脑登录也不会重复弹。
老账号这一列是空的,升级后第一次登录会看到全部更新。

发新版的做法:改 `web/src/changelog.js`,在 `CHANGELOG` **最前面**加一条:

    {
      version: '1.6.0',        // 版本号往上加,右下角显示的就是最新这一条
      date: '2026-09-01',
      title: '一句话说清这次改了什么',
      items: ['用大白话写「用起来有什么不一样」,别写实现细节'],
    },

其它什么都不用改:版本号、自动弹窗、「新」标记全部跟着这一条走。

## ABA ASIN 视图

进入「ABA 报告 → ASIN 视图」上传原始 CSV 周报。A1 读取 ASIN，C1 读取日期范围与报告周数，不依赖文件名。支持空周报；同 ASIN 同周重传更新，数据按账号和站点持久隔离。

也可上传合并 XLSX：每行 AI 列为 ASIN、AJ 列为时间范围（如 `周 35 | 2026-08-23 - 2026-08-29 2026`），按原表头保留其余指标。系统先预览拆分后的周报，再统一保存；不从工作表名或文件名推断数据。合并表中同 ASIN 同周的明细重传会替换原周报。

显示方式可切换“机型分类汇总”，按 ASIN 分开统计每个机型的搜索词数量、曝光、点击、购买及比例，展开查看分类内的搜索词。未识别到机型的词归为“墨盒 KW 词”，可单独筛选。分类汇总始终统计全部所选周，分页不影响总数。

SKU 库新增末尾可选列 ASIN，在对应 SKU 行填写后可按年份、月份、周、ASIN 和 SKU 筛选。旧的 7 列库存表继续支持，增量导入未包含 ASIN 列时保留原关联。多个 SKU 对应同 ASIN 时显示同一份 ASIN 数据，不重复计数。年份与月份按结束日归属。

市场和 ASIN 的 CVR 均按购买次数 ÷ 各自点击次数计算；品牌占有率按 ASIN 购买次数 ÷ 市场购买次数计算，百分比保留两位小数，零分母显示「—」。同一 ASIN 相同搜索词跨周合并后重新计算比例。机型查询沿用品牌视图 D 库逻辑。

「墨盒型号」从当前账号、站点和日期范围内有关联报告的 SKU 中识别，同品牌、同型号的不同颜色套组可合并。选择型号后，同一个搜索词跨套组合并成一条：同周市场指标只计一次，各 ASIN 指标相加，再重算 CVR 和占有率；多个 SKU 关联同一 ASIN 不会重复累计。若来源市场数值不一致，对应字段及依赖比例显示「—」，展开待核对提示查看各 ASIN 来源值。不同周仍累加各周数据，机型分类汇总和展开明细遵循相同口径。未选择墨盒型号时按 ASIN 独立展示。

验证：`node --test server/tests/abaAsin.test.js`、`npm --prefix web test`、`node web/tests/abaAsin.browser.mjs`。浏览器测试沿用 PLAYWRIGHT_MODULE；可设置 ASIN_SAMPLE_DIR 指向本地原始样本以校验真实报告总数。

ASIN 筛选更新（2026-09-11）：按「墨盒型号 → 品牌 → ASIN → SKU」逐级筛选，型号选项汇集各品牌已关联的型号，品牌采用当前账号、站点的 SKU 库信息。未关联型号的 ASIN 可展开查看并补充资料；选择型号后合并当前品牌筛选范围内的套组。

选择两周或更多时，「多周统计」可切换为周平均。每个搜索词先合并数量，再除以它实际出现的周数，缺失周不按零计入；机型分类汇总为各词周平均之和。数值保留最多两位小数，CVR 和占有率按显示数量重算，明细标注参与计算的实际周数。单周恢复原始数量。

ASIN 大批量上传会自动分批保存并显示进度：每次可选最多 200 个文件，合并 XLSX 可包含最多 5,000 份 ASIN 周报；单文件 10 MB、文件合计 30 MB，合并表仍限制 100,000 行及解压后 30 MB。每批独立保存，中途失败会提示已完成数量并保留文件，重试不重复累计。
