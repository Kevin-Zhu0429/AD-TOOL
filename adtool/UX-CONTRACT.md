## 开设广告合并与 SB 品牌广告（2026-10-16）

- 业务依据：用户要求把自动、手动广告两个板块合并，加入品牌广告（SB），自动广告瀑布流保留；用户确认方案 1A（一页切换、一个总表 SP/SB 各一页）、2A（批量开 SB 新活动）、3A（上传一次后台 SB 批量表读品牌素材，按站点共用）、4A（先做集合与视频）。附件「品牌广告数据模版.xlsx」只作为列名、实体层级和素材格式的依据。
- `AdsPage` 是开设广告页的唯一外壳：读一次词库 / SKU 库 / 广告组合库，下发给 `BuilderPage`（SP 自动）、`ManualPage`（SP 手动）、`SbPage`（SB），三者都常驻挂载、只隐藏，切换不丢内容；生成按钮只在外壳。未改动过的类型不参与生成，用过的类型有待处理任务就整体拦住。导航 `manual` 入口跳到本页的 SP 手动标签；SP 手动和 SB 沿用「手动广告使用权」。
- `shared/sbEngine.js` 写「品牌推广多个广告组广告活动」页，表头与后台下载一致（64 列，不含指标列）。每条活动：广告活动 → 4 行按广告位调整竞价（搜索结果首页首位 / 其他 / 首页 / 商品详情页，勾了竞价优化则不写）→ 广告组 → 广告（自动合集 / 手动合集 / 视频）→ 关键词或商品定向 → 否定关键词。SB 无活动级否定，词库和本任务的活动级否定都写到广告组并去重；否定 ASIN 不写并在预览提醒。
- 瀑布流按选定广告位的档位一档一条活动，命名 `活动名-Tos20`；目标 CPC 模式出价 = CPC ÷ (1+该活动最高正向溢价)。手动合集要 3–10 个 ASIN，视频要 1 个 ASIN，落地页按站点拼 `https://www.amazon.xx/dp/ASIN`；推广商品填 SKU 时从 SKU 库取 ASIN。
- `server/src/sbAssets.js` + `sb_brand_assets` 表按站点存一份品牌素材（品牌实体、徽标、视频，徽标裁剪从已有广告行抄），浏览器解析后只上传这几项；读需手动广告使用权 + 站点可读，写需站点可写。
- 验证：`web/src/sbEngine.test.js`、`server/tests/sbAssets.test.js`，以及用用户模版在浏览器里上传素材、开 4 档瀑布流并下载总表核对。

## 首页圆形功能轮播（2026-10-13）

- 每个入口带有 `CardAmbientBackground` 装饰背景，背景不接受输入、不参与辅助技术内容、不改变导航。用户提供的颗粒渐变、Aurora 与 GradientWaves 着色器由一个共享 WebGL2 渲染器驱动，同一张卡片的 2D 切片必须取自完全相同的一帧。Shader 保留原始算法及配色，主题与正文区域渐隐仍沿用共享变量。按钮“暂停动效 / 继续动效”同时控制圆环和背景；离开可视区域、后排或标签页后台停止更新，减少动态效果时只绘制静态帧。WebGL2 不可用或上下文丢失时显示静态主题渐变，入口操作继续可用。卸载首页时释放渲染上下文、监听器和缓存。浏览器检查验证真实像素随时间变化、单一 WebGL2 上下文、切片同步、暂停、减少动态效果、窄屏和主题/站点切换。

- 用户指定将首页入口改为 React Bits CircularCarousel 试用效果。`HomePage` 是入口名称、说明、站点与权限的唯一所有者，继续通过应用的 `onNav` 导航；`CircularCarousel` 只维护展示和选择，不调用业务接口。普通账号不能通过轮播看到未开通功能或超级管理员入口。
- 两侧卡片点击只聚焦，正中卡片点击与回车直接进入；拖动后的点击必须被抑制，防止意外跳页。左右按钮和所有功能选择按钮提供无需拖动的操作路径；完整功能说明持续显示在轮播下方。
- 默认缓慢自动转动，悬停和键盘聚焦暂停；点击功能选择或左右按钮后停止自动转动，用户可明确恢复。离开可视区域和浏览器后台停止绘制。减少动态效果时关闭自动转动与入场，手动切换直接就位。屏幕阅读器不自动播报每次自动转动。
- 站点切换更新入口标题与描述，主题切换直接读取共享 CSS 变量。手机侧面卡片在轮播内部裁切，不造成全页横向滚动；页面继续由 `.shell-main` 滚动。验证入口为 `web/tests/homeCarousel.browser.mjs`，使用模拟账号和数据，不接触真实账号及数据库。

## FBA 超龄仓储费共享计算（2026-09-23）

- 超龄仓储费是独立顶层页面，使用可用页面宽度展示数据表；原小工具页仅保留 Excel 合并。库存表在浏览器解析，支持 ZIP 中的 CSV/XLS/XLSX 及直接导入表格，并由服务端复核计算；导入创建新的共享批次，所有已登录账号可导入，默认读取最新批次。旧批次保留在数据库。
- 市场费率与计算规则统一由 `shared/agedStorageFee.js` 维护：每月 15 日快照、先进先出；7 天日销为 0 时取 14 天，两者都为 0 时固定 0.14；每行保存日销来源。图片中的 AE 费率为 0 / 0.05 / 0.18 / 0.18 美元/件/次。
- 全部已登录账号可查看和修正全部市场、品牌的共享结果，不受账号负责站点限制。品牌和市场仅用于页面筛选。市场费率在可展开表格中按库龄阶段列出。
- 运营可把“是否有特殊情况”改为“是”并填写修正日销与备注；最终计算日销和两项费用即时跟随修正值。筛选可查看全部、“是”或“否”的行；修正日销后行留在原位并高亮，不会因排序或“特殊情况”筛选立即跳走；点击“重新排序”（或切换筛选/排序、刷新）后才按最新数值重新排列，导出始终按最新数值排序。单行修正保存在服务器，按修订号拒绝覆盖别人刚保存的变更；遇到冲突须刷新。未填写有效修正日销、尚未保存或保存失败时禁止导出。导出当前筛选下的全部行，不受页面分页限制。
- 新批次的日期和库龄场景仅在导入时生效。列表可按套均费用、费用总额、最终计算日销升降序排列；导出遵循当前筛选和排序。每页 50 行，在表格内部滚动；加载、空状态、读取失败、保存失败及修正未完成均给出页内文字反馈。验证入口：`web/src/agedStorageFee.test.js`、`web/src/agedStorageImport.test.js` 与 `server/tests/agedFees.test.js`。
- 库存原表可能有大量与计算无关的列，浏览器只发送市场、SKU、日销和 8 个库龄值。导入按不超过 128 KiB 的请求分片暂存；全部分片到齐且服务端整表校验成功后，才把新批次展示给所有账号。失败时清理暂存，避免单次请求触发前置服务的 413 大小限制。前端遇到尚未更新的后端返回分片入口 404 时，使用紧凑数据调用原导入接口。
- 市场代码第一个词是品牌、最后一个词是市场；DE、FR、IT、ES 按 EU 费率计算，市场列仍显示站点本身。已导入的旧批次在读取时按此规则补算费用。
- 未配置费率或无法从市场代码识别出受支持市场的 SKU 不阻断整表导入；保留市场与库存数据，费用和可售月留空。运营仍可修正日销并导出该行，导出的费用单元格为空。

## 操作日志与账号统计（2026-09-15）

- `audit_log` 与 `server/src/auth.js` 是全站操作记录的统一入口。所有服务端数据维护操作继续在成功提交后记录；自动广告、手动广告、广告优化与小工具等本机处理板块通过受控事件接口记录打开、读取和导出摘要，不记录文件内容、搜索词、密码或密钥。
- 操作统计和明细仅允许 `owner` 角色通过 `/api/auth/audit` 读取；普通账号不显示入口，直接请求返回 403。客户端隐藏不作为安全边界。
- 账号统计包含每个现有账号近 7 天、近 30 天操作数和最近操作时间，未操作账号也显示为 0。明细按时间倒序展示最近 500 条，可按账号和 7/30 天筛选；时间使用服务器本地时间。
- 日志记录包含操作者、动作、对象、结果成功后的业务摘要与可选站点。日志不可编辑；账号删除或停用不应改写既有事件。
- 验证入口为 `server/tests/audit.test.js`，覆盖 owner-only 读取、账号统计窗口、受控前端事件与站点越权拒绝。

- 摸鱼率（2026-10-13）：用户确认采用原次数方案，分子仅包含 `login`、`open`、`logout`，分母为同一账号、同一 7/30 天窗口的全部已记录操作。顶部按各账号分子之和除以总次数计算，不平均各账号百分比；沿用现有日志时间和账号范围。无操作显示“—”，其余以一位小数百分比并附分子/分母显示。只统计次数占比，不自动推断工作时长、设置等级或修改既有日志。权限沿用 owner-only，历史记录直接计算，无需迁移。

## 账号角色与删除（2026-09-21）

- 只有超级管理员可修改其他账号的角色、站点、状态和删除账号；不能修改自己的角色、停用自己或删除当前登录账号。服务端权限校验是安全边界。
- 超级管理员改为国家管理员或运营时，角色和至少一个负责站点必须在同一次保存中提交，避免把数据库中的 `ALL` 错当成可选择的负责站点。纯商品部账号日常编辑仍可不分配站点。
- 删除是不可恢复的永久操作，必须使用站内确认弹窗明确账号和影响范围。账号私有的 SKU、ABA 报告、广告组合及该账号的船长店铺国家分配一并删除；仍被其他账号使用的共享库存来源、共享词库、产品数据及历史操作日志保留，并清除对已删除账号的外键关联。
- 删除成功后留在账号列表、刷新统计并显示持久结果提示；失败时弹窗保持打开并允许重试。验证入口为 `server/tests/accounts.test.js`，覆盖 owner-only、自删保护、角色降级原子提交、私有数据清理和共享记录保留。

- 库存接口每页 100 条并按 `max_result` 翻页；时间跨度拆成最多 30 天。首次回查天数可配置，后续从最后成功时间前 5 分钟重新拉取，重复数据通过店铺+SKU 快照覆盖。
- 大陆欧洲详细站点返回同一份共享 FBA 库存；每个店铺组+SKU 只采用最近的一份快照，不把 DE/ES/FR/IT 的相同 `fulfillable_quantity` 相加。在途仍为该快照的 `inbound_shipped_quantity + inbound_receiving_quantity + inbound_working_quantity`。同一份数量分别写入 ES/DE/FR/IT 所指定账号的对应国家同名 SKU，不写入该账号未负责的国家。UK 使用独立店铺组；US、CA、AU 也按国家独立。
- “同步全部库存”对每个真实库存来源只调用一次，再把快照应用给所有国家负责人；普通账号同步时只应用自己的国家分配，不会更新其他负责人的 SKU 库。
- 只更新网站中已存在、账号+品牌+SKU 匹配的行；不创建新 SKU，不改品牌、型号和套组。唯一且有效的 ASIN 可补入；欧洲来源 ASIN 冲突时保留网站原值。
- 单店失败保留上次快照与网站库存，其余店铺继续完成；界面报告失败数量。并发点击同一账号只运行一次，令牌在过期前缓存，401/403 时刷新后仅重试一次。

## SKU 库与广告优化库存风险联动（2026-09-16）

业务依据：用户反馈上周期有 SKU 断货但未察觉，广告仍产生 18 次点击且无订单；当前库存 API 已接入，要求广告优化 SKU 矩阵与 SKU 库库存联动，并高亮在库为 0 的 SKU。库存字段来源与站点、账号边界沿用上面的“船长 BI 库存同步”约束。

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |
|---|---|---|---|---|
| 库存判定 | `shared/skuMatch.js` 的 `isZeroStock` / `summarizeSkuInventory` | 当前账号、当前站点 SKU 库的 `stock` 字段 | 明确为 0、正库存、未填写、未关联 | 单元测试 |
| SKU 库提醒 | `SkuPage` + `.sku-zero-*` | 当前列表库存 | 已断货、在库 0 但有在途 | 浏览器浅色/深色 |
| 广告矩阵联动 | `OptimizerPage` → `optApp` | `/api/skus?marketplace=站点` 与批量表广告 SKU | 按 SKU、按 ASIN 聚合、仅看在库 0 | 单元测试与浏览器流程 |
| Feedback | SKU 矩阵持久页内摘要 | 零库存项的本周期广告指标 | 项数、点击、花费；无风险时不显示 | 状态与窄屏检查 |

- 只有 `stock` 明确返回数值 0 才判定“在库 0”；`null`、空字符串或未关联 SKU 库表示未知，不得误报为断货。
- 在库为 0 即进入风险提醒；`transit > 0` 时保留在途数量并继续提醒。“已断货”仅用于在库为 0 且没有在途数量的 SKU。
- SKU 比对忽略首尾空格和大小写，与后端 SKU 判重口径一致。按 ASIN 查看时，只要聚合项里任一 SKU 在库为 0，该项即高亮并显示受影响 SKU 数。
- SKU 矩阵提供“在库 0”筛选、库存列和持久风险摘要；摘要用当前周期数据汇总受影响项的点击与花费。风险状态不自动暂停、启用或修改广告，操作仍由用户决定。
- SKU 库同步、导入、编辑或删除成功后，当前已挂载的广告优化工作台重新读取当前站点 SKU 库；旧请求不得覆盖新请求。

## Detection contract

- 先独立解释搜索词，再与投放比较；活动不能改变搜索词的型号识别。

- 无可识别型号的普通词不作为跑偏记录。匹配成功的词仍可在搜索词明细查看。
- 状态不会自动创建否定。原有词组、精准按钮由用户决定使用；本次不改变导出或否定行为。
