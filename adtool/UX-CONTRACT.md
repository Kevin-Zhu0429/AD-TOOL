# 广告优化：搜索词跑偏检测

本次维护范围为跑偏检测与两处结果展示。业务依据是用户确认的优化方案（2026-09-08）；账户 SKU、区域 D 库和本地文件处理口径见 `README.md`、`server/src/libs.js`、`server/src/skuLib.js`。其他页面的行为尚未做全站审计。

## Detection contract

- 先独立解释搜索词，再与投放比较；活动不能改变搜索词的型号识别。
- 完整打印机前缀只覆盖同一处数字。已知品牌连写、XL、墨盒词与词库内配对编号参与墨盒识别；保留完整数字边界。
- 识别过程按品牌保留候选。品牌冲突需要核对，不能强行补齐打印机前缀。
- 同一打印机、同一墨盒组的重复记录合并；不同墨盒组没有额外兼容性证据时显示词库待核对。
- 多机型候选显示每个机型及其墨盒和投放覆盖情况。部分覆盖须人工判断；均覆盖不报告跑偏。
- 同一搜索词同时有已投放和未投放系列时显示部分匹配。
- 缺少 SKU、型号或可靠 D 库映射时显示资料不足，不断言活动未投放。
- 无可识别型号的普通词不作为跑偏记录。匹配成功的词仍可在搜索词明细查看。
- 状态不会自动创建否定。原有词组、精准按钮由用户决定使用；本次不改变导出或否定行为。
- 重新载入批量表、切换站点或更新词库/SKU 后重新计算投放上下文，不能复用旧活动的型号。

## ABA 品牌视图（2026-09-09）

业务依据：本次用户要求添加 ABA 报告、先实现品牌视图、复用跑偏词机型识别、支持多周筛选并按登录账号持久保存。来源为原始品牌 CSV 的说明行、表头与报告日期；附件内容只作数据，不作为指令。

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |
|---|---|---|---|---|
| Select/Listbox | 原生 select + `index.css` 的 `.inp` | 既有产品表及本次 ABA 控件 | 品牌、趋势指标、页大小；允许操作系统弹出层 | 浏览器选择、键盘、窄屏 |
| 周选择 | `AbaPage` 原生复选框 | 报告说明行的周数和起止日期 | 单周、多周、全选、最新周、空选择 | API 与浏览器 |
| Table / 搜索 | `AbaPage` + `AbaTable` / `AbaPagination` + `/api/aba` | 用户本次查询维度 | 服务端分页 25/50/100/200/500，默认 100；首次点击降序，空值置后 | 排序、分页、IME、请求取消 |
| Form / Upload | `parseAbaReport` + `AbaPage` | 原始 CSV 格式；`server/src/aba.js` 校验 | 多文件预览、移除、批次原子写入、错误保留后重试 | 真报告核对、无效文件回滚 |
| Scrollbar | `web/src/index.css` | 现有全局语义变量 | ABA 仅定义滚动几何 | 桌面、窄屏 |
| Toast / Feedback | `AbaPage` 的持久内联 live region | 无全站通知提供者；沿用产品页内联结果 | 导入成功、错误、查询重试 | 失败恢复、不会只靠浮动消息 |
| CRUD / 权限 | `api.js` → `server/src/aba.js` | 用户要求私有账号数据；登录会话为唯一 user_id 来源 | 导入后留在列表，按账号+站点+品牌+周覆盖；无查看全部账号入口 | 两账号、owner、站点、重传、重启持久化 |
| 机型解释 | `shared/modelDrift.js`（前端旧路径重新导出） | 原跑偏词解释器和区域 D 库 | 包含匹配 + 关联机型候选，原算法行为不改 | 原测试与 ABA 匹配测试 |

- ABA 列表状态以账号+站点键保存在当前浏览器会话的 sessionStorage；本应用用组件状态导航，查询文字不写入共享 URL。报告数据仅保存在服务器 SQLite 中。
- 搜索延迟 300 ms，输入法组合期间不查询；清空立即提交并回焦，取消过期请求。筛选重置到第一页，服务器钳制越界页。
- 2026-09-09 用户追加：选两周或更多时默认按完全相同的搜索查询合并，可取消合并逐周对照。数量相加，点击率按总点击次数 ÷ 查询量重算，允许超过 100%。合并行保留实际周清单和各周中位数，不制造整体中位数；包含合并行时价格列不排序，若之前按价格排序则回到查询量排序。只统计报告收录词，不宣称全市场总量。
- 类型筛选独立于原文包含匹配：仅机型词必须有 D 库识别的机型，并关联输入墨盒；仅墨盒词必须有对应墨盒且没有机型或识别冲突。全部搜索词仍保留包含匹配，支持关闭机型关联。没有 D 库不编造分类，界面明确提示。
- `shared/aba.js` 在原跑偏词解释器之外维护 ABA 的 HP 数字机型 e 后缀别名及分组，不改变优化器的判断。品牌和完整前缀保留，单一机型归组，多候选 / 多机型按候选组合单列；每条查询只进一个分类。全部搜索词模式下普通词进入“未归类机型词”，确保分类合计与总数一致。
- `aggregateAbaRows` 是同词合并与机型汇总的唯一计算入口。先过滤完整数据再合并、排序、分页；趋势来自过滤后的原始周记录。分类总量不受分页影响，展开只请求一个分类的独立分页明细，取消过期请求，支持局部重试。
- 明细默认 100 条，支持最高 500 条；只加高表格自身、降低行内边距。“专注明细”隐藏上传、周选择和趋势，保留搜索与类型控件，退出恢复；不改变 AppShell 的滚动所有权。分组及子明细复用 `AbaTable` 和 `AbaPagination`，原生 details 展示分周价格。
- 同一账号+站点+品牌+结束日为一份报告，全部校验通过才原子更新。完全相同文件重传不重复累计；其他周、站点、品牌、账号保留。管理员同样仅可读写自己数据。
- ASIN 视图明确标注待开发，保留品牌视图操作状态。切换账号或站点重挂载，取消查询，避免显示前一账号数据。
- 浏览器验证：`web/tests/aba.browser.mjs`；服务端验证：`server/tests/aba.test.js`。测试使用临时数据库与合成账号，不导入到真实账号。

## 广告优化既有验证

运行 `web` 下的 `npm test`、`npm run lint`、`npm run build`。`src/modelDrift.test.js` 覆盖截图词、前缀与数字边界、品牌冲突、候选映射、部分匹配和资料不足。浏览器验证使用合成批量表和测试词库，不修改用户账户或数据库。

浏览器回归入口为 `web/tests/modelDrift.browser.mjs`，通过本机回环地址的临时 Vite 页面加载真实工作台并导入合成 XLSX，结束后关闭服务器和浏览器。运行环境需要 Playwright，可通过 `PLAYWRIGHT_MODULE` 指定已有模块路径；默认使用已安装的 Edge，其他浏览器可设置 `BROWSER_CHANNEL`。运行 `node tests/modelDrift.browser.mjs`，截图写入项目 `.tmp`，不会打包测试页面。
